# Implementation review and deployment corrections

Date: 2026-09-17. Scope: extras-only runtime, actual Klippy integration, and
the deployed single-FPS OpenAMS macros. No tracked Klipper source was changed.

## Findings corrected

1. Managed macro status used Klipper's cached wrapper: a real macro observed
   `[0, 0]` across a status-changing command. The adapter now supplies the live
   wrapper and the regression observes `[0, 1]`.
2. Cancellation/failure could allow later commands inside legacy helpers and
   queued template actions. Admission checks now guard each boundary and queued
   callback, and paused managed macros cannot spawn. Cleanup remains available
   through narrowly scoped native recovery and virtual-SD error handlers.
3. Complete API scripts could execute their prefix before detecting an unclosed
   block, and overlapping submissions created runs before owning the mutex.
   Complete preflight and serialized run creation now precede execution.
4. Virtual-SD's global source flag could misclassify unrelated API/child input.
   Real worker greenlets and bound source identity now determine ownership.
   Implicit EOF joins use the file's run, preserve error status, invoke configured
   cleanup, and cannot report success after a dependency failure.
5. Ordinary print lines accumulated toward a 2 MB block limit, and completed
   runs accumulated indefinitely. Limits are now per captured block and bounded
   to 64 recent runs, without evicting active/unwinding contexts.
6. Helper return replies could leak their last device subcommand's reply.
   Replies now belong to command frames; status/result snapshots are detached.
7. Jinja `with` output was discarded and child namespaces could share mutable
   locals. Both are corrected. Unsupported inline statements and output-producing
   filter/call blocks fail clearly before execution; legacy templates are unchanged.
8. The rewritten standalone unload omitted OAMS transport. It now completes
   unloading, refreshes sensor/driver observations between phases, and aborts
   subsequent toolchanges on failure. Only loading overlaps nozzle cleaning.
   The previously active 150 mm unload assist is restored; homed/heated/unpaused
   and group guards precede hardware commands. Optional sensors remain disabled.

These are code findings and reproduced test mechanisms, not claims that the
printer physically experienced each failure.

## Remaining limits

The OAMS MCU connection error blocks live workflow validation. Initial deployment
also reproduced it with the original configuration; earlier CAN discovery found
the printer/toolhead but not configured OAMS UUID `66e4a3d0cd57`. Resolve the OAMS
power/CAN connectivity before trying a physical toolchange.

Managed macros with children cannot execute inside another child. In particular,
invoke the supplied `T0`–`T3` from the default routine. Commands share the real
motion planner and hardware; software cancellation does not prove physical stop.
Geometry, material tuning, driver cancellation, and physical sensor behavior
still require supervised hardware checks.
